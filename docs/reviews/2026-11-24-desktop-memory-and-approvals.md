## 1. 审批放到输入框上方，历史保留结果（P1）

用户报告在多段输出之后要往上翻。源码解释了位置：消息卡先加标题和正文，轨迹随后固定插到索引 1。审批按钮位于轨迹内；等待文案还明确指向“上方”。因此即使滚到底部，长正文仍会把按钮隔在视口外。该结论来自布局顺序，本轮没有采集桌面截图。[消息卡](https://github.com/lbg2002/gnome-quick-chat/blob/d96989c/ui/messageCard.js#L257-L276) · [轨迹插入位置](https://github.com/lbg2002/gnome-quick-chat/blob/d96989c/ui/tracePanel.js#L139)

在 ChatPanel 的消息滚动区外、输入行正上方预留一个仅在有待办时出现的审批区。取当前会话、回合和 requestId 对应的请求，复用原有问题表单和批准/拒绝回调。历史轨迹只显示状态和结果，同时只挂载一个可操作表单。并发时显示“待处理 1/3”，按到达顺序处理，每项保留独立草稿。完整命令、目录和参数可展开，超长详情在表单内部滚动，操作按钮保持可见。

提交后禁用重复点击，按后端对应的确认语义推进队列。区分工具审批、问题答案已送达、超时和取消。面板关闭后重开应恢复当前待办；切换会话、取消回合或锁屏时解除旧按钮绑定。用户正在读旧回复时保留阅读位置；键盘可直接进入待办，Enter 在普通输入框内不得隐式批准。

验收用例为“输出超过两屏 → 审批 A → 继续输出 → 审批 B 和提问 C”。在底部和上翻位置分别触发，均能在输入框附近完成操作，检查迟到确认、拒绝、重复点击、面板重开和焦点恢复，最后在 GNOME 50 Wayland 验证。

## 2. 公共记忆与“我的电脑”档案（P1）

现有 CLI 会加载本会话上下文或续接远端会话，OpenAI 从本地会话构建预算内消息。桌面提示词、模型缓存、会话历史已存在；在四个后端的发送路径中未找到共享的应用映射、成功操作记录或按需检索入口。切换后端后的实际遗漏要结合具体会话判断。0.3.6 已能在输入框直接处理“打开浏览器”，该分支查询 HTTPS 默认应用并向桌面提交启动请求，带附件、编辑旧问题、其他应用以及不匹配短语不会进入这个分支。[CLI 上下文](https://github.com/lbg2002/gnome-quick-chat/blob/d96989c/backends/baseAdapter.js#L70) · [浏览器分流](https://github.com/lbg2002/gnome-quick-chat/blob/d96989c/extension.js#L1448-L1451) · [启动结果](https://github.com/lbg2002/gnome-quick-chat/blob/d96989c/extension.js#L1495-L1529)

“我的电脑”呈现模型积累的 Markdown 笔记。每个后端都能看到同一份本机索引以及当前工作区索引，再按任务阅读相应笔记。模型从用户纠正、工作习惯和已验证的工具结果中自行提炼经验；用户可以直接阅读、编辑、撤销或要求忘记。完整读写流程见第 4 节。

## 3. DSH 的审批、工作目录与桌面打开（P1）

## 4. 模型自主维护的 Markdown 长期记忆

**状态**：v0.3.6 已有本地历史与远端续接。以下是待实现的随问公共记忆设计。开启自动记忆后，模型自己决定值得记什么、怎样概括、归在哪个主题，以及何时修订旧结论。普通写入自动完成，用户可在事后查看差异和撤销。

### 参考行为

ZCode 在成功回合结束后回顾交流，决定是否提取可复用经验。Claude Code 在会话开始读取简短的 MEMORY.md 索引，再按需打开和更新主题笔记。随问采用这两种行为，另加本机级作用域，使桌面经验能跨项目、跨后端复用。Codex 的 AGENTS.md 用于项目指令，在随问中与自动积累的经验分别加载，各自保留原有权限语义。[ZCode Memory](https://zcode.z.ai/cn/docs/memory) · [Claude Code 自动记忆](https://code.claude.com/docs/en/memory) · [Codex 项目指令](https://developers.openai.com/codex/guides/agents-md/)

### 地址和内容

默认物理根目录是 `~/.local/share/gnome-quick-chat/memory/`，通过现有 getDataDir() 跟随 XDG_DATA_HOME。下面的主题名和条目内容只是示例，模型可按需要创建、重命名或合并主题。用户可以用任意编辑器修改原文。

```text
memory/
  MEMORY.md                           # 我的电脑：常用主题、适用情境、相对链接
  desktop-apps.md                     # 应用识别、启动经验和例外
  preferences.md                      # 用户明确表达的长期偏好
  projects/<workspace-id>/MEMORY.md    # 当前项目的索引
  projects/<workspace-id>/preview.md   # 该项目才适用的预览方式
```

例如，模型在桌面回执显示启动请求已受理、用户又确认窗口出现后，可以在 desktop-apps.md 中写下：“用户说‘打开浏览器’时希望打开系统当前的默认浏览器。已在这台电脑确认，从桌面查询 HTTPS 关联并提交启动即可。下次优先走这条路径，避免重新枚举浏览器。”如果只有启动回执，就只写已观察到的结果。索引中只需一行“[浏览器与应用启动](desktop-apps.md) · 打开本机应用前查阅”。命令可以作为 Markdown 代码块保存，同时写明工作目录、适用条件和验证结果。命令的执行仍经过当前后端的正常权限流程。

### 切换后端时如何读

1. 随问在 BackendClient 分发请求前解析本机与当前工作区根目录，使用规范化工作区路径生成稳定 ID。给模型的入口为 `memory://computer/MEMORY.md` 与 `memory://project/MEMORY.md`。每次新建、恢复或切换后端均传入允许该端点读取的索引、读写地址和可用操作。端点共享设置同时约束索引标题与正文。
2. 模型根据当前任务和索引描述决定打开哪些相对链接。已有 CLI 会话也检查索引版本。索引和主题摘录独立计入预算，优先保留当前问题。普通聊天可直接跳过主题读取。
3. 有记忆工具通道的适配器通过宿主的 list/read/edit 操作读写。对当前缺少自定义工具回传的 CLI 或兼容 API，采用可实现的统一后备路径：宿主先给同一后端发起无业务工具的短请求，让模型从允许的索引中选择主题或返回空列表；宿主读取所选 Markdown，一次性随正式任务传入。只在普通任务提交前执行选题，不重发已执行的任务。索引为空时直接开始正式任务。SDK 工具挂载能力须逐个验证。
4. 只读执行模式下，模型通过同一记忆通道更新随问私有笔记。该能力由自动记忆开关单独控制，宿主仅接受当前作用域内的 Markdown 相对路径。模型无需知道真实用户名，也无需获得通用文件写权限。

### 模型何时写、怎样维护

成功回合结束后，宿主异步调度同一后端进行一次有限的记忆整理。输入包括用户本轮要求与纠正、已验证的动作结果、相关索引和旧笔记。整理使用独立上下文，无桌面操作工具；额外模型调用计入用量。浏览器本地快捷路径没有模型回合，可将精简的启动回执留给下一次同端点整理。关闭自动记忆时停止调度，取消或截断的回合不自动固化未完成结论。

模型可选择零修改、创建主题、修改原段、合并重复笔记，或根据用户纠正删掉过时内容。稳定经验写全局，项目特有做法写当前项目；当前打开的窗口、临时错误和未经验证的猜测不应当作长期事实。用户说“记住……”或“忘记……”时优先处理，待宿主落盘后显示结果。日常自动写入只显示“已更新记忆”与可展开的 Markdown 差异，无逐条确认步骤。

后备写入通道使用独立整理请求返回受限的文件变更集，包含相对路径、基础版本与模型撰写的 Markdown 段落。通信封装可采用 JSON；磁盘上每一篇记忆及索引均为 UTF-8 Markdown。宿主只消费整理通道的完整结果，验证路径、大小和版本。普通回答里的示例代码块、附件和工具输出不会被解析为写入操作。

### 用户控制与文件一致性

“我的电脑”支持打开目录、搜索 Markdown、查看最近变更和撤销。用户可以直接编辑文件；提交前再次比对内容摘要，遇到手工编辑或者另一后端先写入就重新读取，让模型基于最新正文合并。每批变更绑定回合与操作 ID，串行提交，私有目录 0700、文件 0600。用可恢复的事务记录协调主题与索引更新，重启时完成或回滚整批；写失败保留旧版本。同一文件的外部编辑使摘要缓存失效。

用户要求忘记时同步更新主题和索引，清理相应缓存及可还原这条内容的撤销副本，阻止较早排队的整理任务回写。已含旧记忆的原生续接失效，下次从允许的本地上下文重建，过滤已删除的记忆摘录。此前发给提供方的请求仍受该端点自身的数据保留规则约束。分享范围按端点设置，自动学习限于已授权的上下文；凭据和私密附件原文不用于整理。

### 发布验收

- 用真实发送入口覆盖四后端之间 12 种有向切换。后端 A 从一次有证据的纠正自主写出 Markdown；后端 B 在新聊天中看到同一个索引与写入地址，读取主题、补充一句，切回 A 可见更新。
- 用“第二次打开浏览器”验证模型读到了上次经验，应用枚举次数为零；系统默认浏览器改变后仍按当前关联启动。无新知识的一轮允许零文件变更。
- 用只读 DSH 和仅支持普通消息的 HTTP 测试端点分别验证按需读取和自动写入，记录额外请求次数、用量与时延。模拟整理失败，检查正常回答完整、未写成功的记忆未被报告为已保存。
- 在用户手工编辑、两后端并发写、崩溃、流截断和忘记后旧任务迟到等情况下验证无覆盖、无半成品索引、无已删除内容回流。所有测试写入隔离目录；桌面和真实后端另行实测。

## 复审修复

- 恢复检测到手工修改时，将事务日志归档为同目录的 .conflict 文件并保留原笔记，其他项目可以继续打开记忆。宿主在提交前验证新增或删除主题与 MEMORY.md 的链接。回归覆盖重启重放、手工编辑、跨项目访问和三种无效索引变更。
